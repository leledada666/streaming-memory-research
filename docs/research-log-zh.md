## 1. 一句话主张

冻结自回归骨干 + 每步注入外部流的记忆上限，不是由 KV cache 的**存储容量**决定，而是由两件更基本的事决定：**寻址（addressing）**和**读取（read）**。信息存得下，但 query 既找不到那个位置，也读不回来。现有流式工作几乎只优化 storage（缓存更多、追加更快），把 addressing 当成了免费变量；这正是 L≈10 墙的来源。

三段分离：

| 环节 | 问题 | 现有做法 | 缺失 |
|---|---|---|---|
| storage | 把 m_s 存在哪 | KV cache、旁路残差、ΔK/ΔV | 容量/干扰 |
| addressing | query 怎么找到 s=t-L | 冻结注意力的 RoPE 相位 | **没有可训练的 lag 选择** |
| read | 找到后怎么取出来 | 注意力加权、局部注入 | 远端权重衰减 |

一个接口只有在三段都成立时才有长程记忆。bypass 有 storage，但 addressing 冻结且局部；ΔK/ΔV 有 storage，但 dK/dV 不含位置、无法 addressing；append 有新槽，但 query 仍冻结；shift 把目标搬到当前位置，绕开 addressing；GRU 把 addressing 学进状态；cross-attn 加相对位置后才同时具备可训练 addressing + read。

**深度即记忆（新）**：如果每层可以做一次局部读/写，那么 D 层可以串联出约 D×R 的等效时域。这解释了 E6 的 multis（每层注入）> emb（只嵌一层）：层数就是 hop 数。L=15 可能不是硬墙，而是**没有学会串联**；M16 的 `shift_random` 异常（7+8=15 却到 .601）正是这个机制的线索。若成立，长记忆的答案是“多跳局部操作 + 课程”，不是一次长跳。

**两种寻址必须分开**：
- **位置寻址**（lag recall）：“t-L 时刻那个观测”。需要相对位置信息；冻结注意力只有局部峰，这是 L≈10 墙的来源。
- **内容寻址**（content recall）：“和当前 query 匹配的那个历史 key”。匹配由内容决定，不依赖距离；冻结注意力可能本来就够用，只要 key 在注入后被对齐。
这两个在交易里对应不同问题：前者是“30 分钟前发生了什么”，后者是“上次波动率这么高时发生了什么”。后者更有用，也可能更容易。

## 2. 实测：冻结 Kronos 的注意力是局部的

设置：Kronos-small（8 层 × 8 头，d=512），真实 BTCUSDT 1m token，T=96 bar，batch=32；零训练，直接统计 query(t+L) 对 key(t) 的注意力，按层/头/位置平均。

| L（bar） | 平均注意力 / 均匀 | 最强单头 / 均匀 |
|---:|---:|---:|
| 1 | 2.83× | 12.9× |
| 2 | 2.53× | 7.2× |
| 3 | 2.22× | 7.4× |
| 5 | 1.27× | 3.1× |
| 8 | 1.23× | 2.7× |
| 10 | **1.03×（≈随机）** | 2.1× |
| 12 | 0.81× | 1.7× |
| 15 | 0.92× | 1.9× |
| 20 | 0.77× | 1.6× |
| 30 | 0.56× | 1.5× |
| 60 | 0.50× | 1.4× |

最近 4 个 key 的注意力质量：每层 0.21–0.43。

**第二模型 + 上下文缩放（2026-11-15）**：Kronos T=96 L*≈13.9、T=192 ≈21.6；Qwen2.5-1.5B T=96 5.1、T=192 9.4。L* 随 T 近似线性（Kronos ~0.11–0.15T，Qwen ~0.05T）；随机 token 的曲线几乎相同 → 这是 softmax+RoPE+sink 的架构指纹，不是金融预训练学到的。**“L≈10”不是跨模型常数；T=96 的 L15 墙可能只是刚好超过 R≈14，不是绝对记忆极限。** 需要 M17（T=192/384 的 E6）来判。

同一骨干上的 E6 合成回忆（m_t 每层注入，目标 c_{t-L}）：L=10 测试准确率约 .62，L=15 崩到 .51；15k 步长训也失败（`runs/e6_long_2026-10-20`）。

零训练站点探针（M1b clean，3 seeds）补充：注入幅度对齐到激活尺度（ratio≈1.00）后，L=0 正控 best-head .964、残差流 1.000；L=1 best-head .632、残差流 .990；L=5 .546/.616；L=10 .526/.551；L=15 .527/.537；L=30 .519/.518；L=60 .531/.518。

**置换零分布 + cross-fit（M1b perm）**：64 站点取 max 的 null p99 已经是 .523；L=10 原始 .526，cross-fit 后 **.516**；L=15 .527→** .521**；L=1 .632→.624；L=5 .546→.545。也就是说，L≥10 的自然读在扣除“64 选 max”的选择膨胀后只剩 **+1.6pp**，基本是噪声；L=1/5 的效应可信。**不要把 .526 当作“L=10 还能读”的证据。**

但这是**随机方向、零训练的下界**：E6 训练过的 bypass 在 L=10 的均值是 .553（范围 .521–.622，5 runs），multis 相对 emb 是 +6.8pp；最好种子 .622 不能当均值。E6 的 10→15 衰减是 **.553→.508（均值）**，L=15 已经在 chance。

**训练曲线诊断（2026-11-15）**：L=15 不是欠训。emb L15 在 1200–2000 步从 .50 升到 .54 后进入平台，best .549 @3700，早停后还降到 .540；multis L15 的 loss 在降但 val 在降（记忆化）。L15 的 test 只比 L10 emb 低 .01–.03；真正大的差距是 multis L10 的 test（.566–.622，best-val 比 test 高 .176）。所以“悬崖”没有 headline 那么大，但 multis L10 的优势是真实的。

**唯一还没试的优化路径**：warm-start（保留 L10 的层间分工）、lag 课程（5→10→15）、恢复 L15 的层间 gate 分化（L15 的 8 层 gate 几乎一致 .90–.95，L10 是层 0–4 .97–.99、层 6/7 .77/.46）。M14 就是判这个；阈值：warm-start/课程在 2000 步内 best-val ≥.58 才算“优化可救”，<.57 则证伪。

M12 强制寻址（幅度对齐，注入≈激活范数）：`force` 在 L=0/1/10/15/30/60 全部 **1.000**，`natural` 0.50–0.60，`wrong`（错误 lag）≈natural；把注入放在层 0、读出放在层 7（穿过 7 个真实 block）仍是 1.000。结论：**存储与跨层保持不是瓶颈，寻址才是。** 注意这是上界证明（注入幅度=激活范数）；自然写入的信噪比更低，正在做幅度扫描。

**三量分解（关键）**：

| L | natural（M1b cross-fit） | trained emb | trained multis | force（M12） |
|---:|---:|---:|---:|---:|
| 10 | .516（raw .526） | .524（n=6） | **.605**（n=4；4k `.617`；range .566–.622） | 1.000 |
| 15 | .521（raw .527） | .509（n=3） | .512（n=3） | 1.000 |

- L=10：headroom .484；multis 相对 natural 兑现 .089 → 约 18%；干净的 4k 三点网格是 emb `.520/.521/.526` vs multis `.610/.621/.622`（+9.5pp，3/3）。
- L=15：headroom .479；multis 相对 natural 是 **−.009**，零效应（+.003 vs emb，n_eff=506 时 95%CI [−.06,+.07]）。
- **L=5 的警钟**：emb test `.545`（n=3，val `.658`）与零训练自然读 `.546` 相同 → **adapter 在 L5 没赚到任何 test**；它可能只学到了 val 时段的统计。E2 三段重评会判这个。

所以“墙”不是存储，也不是自然注意力在 15 处突然消失；是**训练几乎无法把 headroom 兑现**。L=10 只有边缘、种子依赖的增益；L=15 完全在 chance。这既可能是寻址几何（没有可学的 lag 方向），也可能是优化（warm-start/课程/gate 能救）。M14 就是判这个。

**统计口径**：`best_val` 比 test 高 .03–.07（55 次 val 选优的 winner's curse），对外只报 test；`n_test`=41,472（L15）/44,032（L10），但按窗口 cluster 有效 n≈506，别把 4 万当独立样本。L10 multis 只有 2 seeds（s2 缺失）。

**幅度扫描（M12d）**：`force` 在 a=0.05×（每维约 1.2σ）时已经 1.000，L=15/30/60 都不衰减；`natural` 在 L≥15 即使把写入放大到 1.0× 也只有 .50–.55；`wrong` 全部 .50–.53。说明自然写入在这个幅度范围内**足够被读出，前提是寻址正确**。force 的 SNR 增益约 96×（96 个 key 收敛到 1 个），是上界；拐点还没找到（unit w ≈0.004× 未测，需补 a=0.01/0.02）。

**E3 弱写 + uniform（本地 CPU，a=0.004/0.01/1.0）**：a=0.004（每维 0.1σ，自然写入量级）force L15 `.984–.985`、L60 `.944–.984`；a=0.01 force `.998`；a=1.0 `1.000`；natural `.50–.56`、uniform `.53–.58`、wrong `.50–.52`。**在自然写入 SNR 下，强制寻址就能读出 .96–.98；瓶颈是寻址，不是写入幅度。** 这把“存储不是瓶颈”从“96× oracle”升级为“自然幅度也成立”。

**FIR-16（本地 CPU）**：最近 16 个 m 的线性滤波（32 参数）在 L=1/5/15 的 ridge acc 全 **1.0000**，最大 |c-coef| 正好落在目标 lag；L=30 应回 chance（待本地补跑）。**GRU 的 .981 只是一条 15-tap 延迟线；固定 lag 不需要循环/注意力，一个 buffer 就够。**

**uniform / shuffled 对照（随机冻结骨干，非 Kronos）**：force 1.000、wrong .50、uniform .56–.58、shuffled .50；幅度 0.05–1.0× 下 force 几乎不变。说明 **force 是地址特异，不是 mass 特异**——把同样的注意力 mass 摊平（uniform）或指向错地址（wrong）都回到 chance，只有“目标地址 + 目标 value”才满分。Caveat：这是在随机 8 层/8 头 d=256 骨干上重建的（原 Kronos 脚本未找到），单 seed，只作方向性复现；需在 Kronos 上补一次。

**M6/M8 冒烟（cross-attn + 相对位置 + lag cue，200 步，单 run）**：l0 `.999`，ℓ=5/10/30 ≈ `.83–.87`，因果差 0。变 lag 寻址看起来可学；但 30 可能也在训练集里，最终要看“训练 5/10、测试 15/30/60”的泛化表。

**M10 内容 vs 位置（冒烟，T=32，200/600 步）**：crossattn 内容 `.664/.642` vs 基线 `.594`（+.07）；GRU 内容 `.624`（+.03）；bypass 内容 `.483`（低于基线）。位置型 crossattn PE `.699`@600 vs nope `.583`；bypass `.512`（低于基线）。L0 正控 1.0，因果检查通过。**但基线（前缀均值）`.594` 太高，疑似任务捷径/泄漏；必须报 arm−baseline，并先诊断基线再跑全量。** 若基线不修，绝对 acc 不可用。

**M2b L=15 完整表（seed0，cap 15k）**：
- `bypass`：val .551 / test .514 / last .504；
- `shift`（把 m_{t-L} 搬到当前位置）：val .999 / test **.695** / last .713，**gap .30**；
- `shift_random`（注入 lag=7，目标 15）：val .674 / test .601 / last .594（疑似组合，见 M16）；
- `gru`（因果 GRU 摘要注入当前位置）：val .999 / test **.981** / last .988，**gap .018**；
- `none`：.502/.500/.496。

同一套参数、同一个 h-only 决策头，只改“写到哪/写什么”，测试从 .51 提到 .98。**存储/容量不是瓶颈，接口才是**：GRU 摘要几乎满分且**泛化干净**（gap .018）；oracle shift 也高但**严重过拟合**（gap .30）；bypass 只有 chance。**GRU 是干净的解，shift 是过拟合的解。** 但 GRU 可能只是固定延迟线，必须用变 lag / 内容寻址（M6/M10）证明它是记忆，不是移位寄存器。

**Shift 复现冒烟（CPU，800 步，B=8，T=32）**：val `.976` / test `.680` / gap `.296`，与 seed0 GPU 的 `.999/.695` 同型。说明 `.68` 可读、但不是干净上限；**val-test gap 真实存在**（时段分布 + 部分规则/捷径），不是优化不足。3-seed 全量（9 run，约 3h）排在 M16/M14 之后；判定：shift 3-seed best-test 均值 L15 >.60 记“复现”，gap>.2 写“可读但不稳定”。

**lag=0 正控（bypass）**：val `.999` / test **.830** / last `.871`。局部注入可学，但**不是满分**；GRU 在 L=15 的 `.981` 仍更强。说明“把信息放到当前位置”是必要条件，但不是充分条件——读出/接口也有成本。这也解释了为什么 bypass 在 L=15 即使有局部注入机会也只有 .51：它不仅要“放对位置”，还要“读得出”。

**M16 组合假说**：`shift_random` 注入 lag=7、目标 L=15，测试却到 `.601`；可能是位置 t 注入 `c_{t-7}`，到 t+8 时用冻结注意力回看 8 步读到它，而 t+8 的目标正是 `c_{t-15}`（7+8=15）。若成立，局部移位 + 局部注意力可串联出更长时域，不需要长程寻址。

**但 lr=1 出现了反例（2000 步）**：val_best `.578`，并没有回到 .5。若最终 test 也高，则 `shift_random .601` 不是“7+8 组合”，而是“任意局部注入”的通用增益或价格上下文偏差；组合假说要降级。等 test 与 lr=7/12 的对照。

结论：L≈10 是可读边界。它同时解释了 E6 的 L=15 墙、multis 比 emb 好（每层多一次局部注入机会）、L=15 门控变平（没有可学梯度）。

**证据纠正（2026-11-15 数据考古）**：此前流传的“Step2 ΔK/ΔV 在 L=15 上准确率≈1.0”**没有可复核文件**；`roadmap_2026-10-20` 里只有 `_smoke_step2_kv.json`（100 步，test_acc .5017）。Step3/Step4 的 JSON/日志也未找到。因此“KV 编辑能绕过读墙”目前是**未验证假设**，不是证据。Step2 真跑（L=15/30，3 seeds，15k/早停）是下一个 GPU 优先项。

## 3. 读路径判据（推导）

设 query t 的注意力权重为 α_{t,s}，注入信号 u_s（近似单位范数），目标位置 s*=t−L。读出：

```
signal = α_{t,s*} · u_{s*}
noise  = sqrt(Σ_{s≠s*} α_{t,s}²) · |u|
SNR(L) = α_{t,s*} / sqrt(Σ_s α_{t,s}² − α_{t,s*}²)
```

c_s 是 iid ±1，所以干扰是同分布随机和，SNR 由 α 的分布决定，不能靠 MLP 后来的非线性“提纯”（data processing inequality）。
- 均匀注意力（t 个 key）：SNR ≈ 1/√t，随上下文变长而下降。
- 局部注意力：α 随 L 指数/快速衰减，SNR 衰减更快。
- 可训练读路径：α 可被学成尖峰，SNR 由 adapter 决定，不由冻结几何决定。

**三个可操作量（把 storage / addressing / read 分开测）**：
- `storage_decodability(L)`：强制注意力落在目标位置后，线性探针能否读出 c_{t-L}（M12）。它只测“存得下/取得出”，与寻址无关。
- `addr_ratio(L)`：α(q_t→k_{t-L}) / mean_s α(q_t→k_s)（M1/M3）。它只测“找不找得到”。
- `natural_read(L)`：原始注意力下的探针准确率。它测两者合起来的结果。

判决：
- storage 高、addr 低、natural 低 → 寻址瓶颈（本框架的预测）。
- storage 也低 → 写入/表示瓶颈，框架需扩展。
- storage 高、addr 高、natural 低 → 读出/价值子空间瓶颈。

## 4. 接口相图（可证伪预测）

记 R≈8–10 为冻结注意力的有效回看；r 为外部流相对骨干 token 的速率；S 为侧记忆容量（bit/slot）。

| 接口 | storage | addressing | read | 预测上限 | 现有证据 |
|---|---|---|---|---|---|
| raw bypass（E6） | 每位置残差 | 冻结、局部 | 远端衰减 | L ≲ R ≈ 10 | L10 .62 / L15 .51（实测） |
| token append（M4） | 新 KV 槽 | 冻结 query，距离 rL | 远端 | L ≲ R/r | M4 对照无效（待重设计） |
| ΔK/ΔV（Step2） | 改写 K/V | **无位置，只改幅度** | 远端 | 不解决 lag 寻址 | 仅 100 步 smoke .5017；旧 1.0 无文件 |
| shift（M2b） | 搬到当前位 | oracle | 局部 | 容量 | 待跑 |
| GRU 摘要（M2b） | 固定状态 | 学进状态 | 局部 | 容量 S | 待跑 |
| cross-attn + 相对位置（M3） | 序列/槽 | **可训练 + 位置** | 可峰化 | 容量 K | 待跑 |
| 微调骨干（M11） | 原 KV | 可训练 | 可训练 | 取决于遗忘 | 待跑 |

预测：
- **P1**：GRU 摘要 / cross-attn 在 L=30/60 仍显著高于 .5，且不随 L 崩。
- **P2**：token append 在 L≈4–8 就崩，比 bypass 更早（距离 2L+1）。
- **P3**：cross-attn 的收益在参数量对齐后仍存在；随机打乱 m 或随机固定 Q/K 时应回到 .5。
- **P4**：在 L=10 训练、L=15/30 测试，raw bypass 不能泛化；摘要/读路径可以（若学到的是通用记忆而非固定延迟）。
- **P5**：冻结注意力的 α 在训练 bypass 后变化有限；若显著变大，说明模型能“掰弯”读路径，理论需修正。

**两个轴，一张相图**：
- `R` = 冻结读路径的有效回看（本模型 ≈5–10）。
- `S` = 侧记忆容量（bit / slot 数）。
- 各接口的上限：
  - raw / past write：`L_max ≈ R`（存储再多也没用，卡在寻址）。
  - recurrent summary：`L_max ≈ S`（与 R 无关，但容量有限；固定 lag 的 shift register 需要 S≥L）。
  - cross-attn + 位置：`L_max ≈ S`，且寻址可训练；比 summary 多一条可检索的地址。
  - ΔK/ΔV：存储随 L 增长，但寻址仍冻结；若没有位置，只能改幅度，不能选 lag。
  - 事件门控：`L_max ≈ S / H(event)`，其中 H 是每个事件的有效信息量；不是时间，而是“值得记的事件数”。

**但 R 不是常数**：Kronos `R≈0.1T`（T=96→14，T=192→22），Qwen≈0.05T。所以“用更长上下文换更远记忆”是可行的，但 attention 成本 O(T²)、KV 显存 O(T)；sidecar 是 O(1) 状态，cross-attn 是 O(K) 槽。**记忆是预算问题**：给定延迟/显存/成本，选 (T, S, K) 的组合，而不是问“哪个架构最强”。

## 5. 为什么这比“更快的 KV cache”重要

原研究把流式当作推理加速：缓存住历史 K/V，每步追加新 token。实测加速上限约 2×（`bench_stream_vs_refeed`），且 13ms vs 60ms 在 1m 决策上只值 0.01–0.3bps。真正的瓶颈不是算得多快，而是**模型能不能用到很久以前的信息**。

如果读路径只有 R≈10，那么：
- 更长的 cache、更大的窗口、更快的追加，都不会提升记忆；
- 只有“把记忆压缩到当前步”或“新增可训练读路径”才会；
- 对交易而言，指望 LLM 从 30 分钟前的 tick 里读出行情状态，是先验上不成立的；必须显式维护状态（波动、订单流、持仓、事件）。

## 7. 什么会推翻这个框架

1. **M2b 的 shift（把目标搬到当前位置）在 L=30/60 也低**：说明存储/读出本身有问题，不能把锅全甩给寻址。
2. **M2b 的 GRU 也崩**：说明任务/优化本身有额外瓶颈，不能把锅全甩给读路径。
3. M3 的 cross-attn 在参数对齐、打乱 m、随机 Q/K 对照下仍赢：才能说“读路径”是因果机制，而不是更多参数。
4. 训练后的 α 在 L=15 显著升高，且 E6 仍失败：说明还有别的瓶颈（如 value 子空间/归一化）。
5. **Step2 真跑后 L=15/30 仍≈1.0**：说明写路径（改写 KV 槽）可以绕过冻结读路径，我的“读墙不可写破”框架需要收窄为“旁路写入不可，槽写入可”。反之若 Step2 也崩，则“必须新增可训练读路径”成立。
6. **Step2 在 rank=1 与 per-sample shuffle 对照下仍赢**：说明只改幅度就能解决，addressing 不是必要条件，三段框架被证伪。
7. **M3 的 position-free 与 with-position 差异不显著**：说明位置/寻址不是因果变量，cross-attn 的收益只是参数/容量，框架需退回“容量解释”。

## 9. 实验规格（可直接交给执行）

### M5 速率相图（回答“bypass 何时才有正当性”）
- 流：每 bar 到来 r 个观测 m_{t,j}=[c_{t,j}, z]，c iid ±1，j=0..r-1。
- 任务 A（聚合型）：y_t = sign(Σ_j c_{t-L,j})，只需要“那一 bar 的多数”。
- 任务 B（顺序型）：y_t = c_{t-L,j*}，j* 固定（例如最后一个子观测）。
- 接口：bypass（bar 内池化为 1 个向量）、append（每 bar r 个 token）、cross-attn（读 rL 个原始观测）、GRU（读 rL）。
- r ∈ {1,4,16}；L ∈ {5,10,30}；3 seeds。
- 预测：A 上 bypass 不随 r 崩（上限 ≈R）；append 上限 ≈R/r。B 上 bypass 在 r>1 直接接近随机；append 也只有 R/r；cross-attn/GRU 受容量限制。
- 同时报序列长度、显存、单步延迟，给“速率–成本”曲线。

### M6 容量曲线（把“记忆”变成可测的容量）
- 任务：回忆 L=30 bar 前的 B 个独立 bit（B∈{1,4,16,64}）。
- 侧记忆：GRU hidden S∈{16,64,256}；cross-attn slots K∈{4,16,64}。
- 预测：准确率转变点在 S≈B（或 K≈B），而不是在某个 lag；同一 S 下改变 L 应平坦。
- 对照：raw bypass（无侧记忆）应在 B>1 时接近随机。

### M7 价格任务保留（机制不能白拿）
- 基线：冻结 Kronos h_t + 线性探针，预测下一根 1m 收益符号（AUC）。
- 处理：先训练 adapter 做合成记忆任务，再冻结 adapter 测同一价格探针。
- 预测：若 adapter 只是加性门控，AUC 退化小；若覆盖残差流，退化大。
- 判据：AUC 退化 >0.02 即视为“有代价”，需在架构里加隔离（gate/低秩/LoRA 式）。

### M8 lag 泛化（区分“延迟线”与“内容寻址记忆”）
- 训练 L=10，测试 L∈{5,10,15,30,60}。
- 预测：固定 shift-register 的 GRU 在非训练 lag 上退化；cross-attn/retrieval 若学到内容寻址，应更平坦。
- 因果：若 GRU 只在 L=10 好，说明它学的是“固定延迟”，不是通用记忆；这对真实流（lag 可变）不够。

### M10 关联回忆（内容寻址 vs 位置寻址）
- 流：m_t=(k_t, c_t)，k_t 从 K=64 个符号均匀抽取（T=96，碰撞少），c_t iid ±1。
- 两种查询：
  - **位置型**：q_t=k_{t-L}，目标 c_{t-L}；模型必须按“固定滞后”找。
  - **内容型**：q_t 从过去随机抽一个 key（不固定 lag），目标是对应 c；模型必须按内容匹配，不能靠距离。
- 臂：bypass（把 (k,c) 注入每层）、GRU（压进状态）、cross-attn（Q=q_t，K/V=过去的 (k,c)）、append。
- 对照：打乱 k、打乱 c、query 给不存在的 key（应接近随机）、key 碰撞率、容量 K。
- 预测：
  - 位置型：cross-attn+位置 > bypass（与 M2b/M3 一致）；bypass 受 R 限制。
  - 内容型：bypass 可能**不需要位置**就能工作（冻结注意力做内容匹配），甚至在长 lag 上也可以；cross-attn 至少不差。
  - 若内容型 bypass 也失败，说明“冻结注意力连内容寻址都做不到”，问题比位置更严重。
- 意义：交易里更有用的不是“t-L 的 tick”，而是“和当前状态相似的历史片段”。如果模型能做内容寻址但不能做位置寻址，产品应该按前者设计。

### M11 微调骨干对照（边界条件）
- 在 E6 L=15 上，放开最后 1/2/4 层（或全部）与 adapter 一起训练，其余冻结。
- 预测：若微调能显著提升 L=15，说明墙是“冻结读路径”的后果，不是 Transformer 的固有极限；若微调也救不回，墙更硬。
- 同时测价格任务保留：微调后 next-return 探针 AUC 是否退化，量化“解冻的代价”。
- 这是审稿人必问的边界，不能省略。

### M13 位置感知的 KV 编辑（Step2 的修正版）
- Step2 的 dK/dV 只由 m_s 逐位置算出，没有位置信息，无法区分 s=t-L 与别的同内容位置；它只能改幅度。
- 修正：`dK_s = MLP([m_s, pos_s])`（pos 可用 RoPE 相位、相对位置嵌入或时间戳），让 key 自带地址；dQ 可选。
- 对照：无位置版（原 Step2）、rank=1、per-sample shuffle、位置打乱。
- 预测：有位置版在 L=15/30 成功，无位置版失败；若两者都失败，说明“在冻结 KV 上写”这条路本身不够，必须新增读路径。

### M16 组合记忆（local shift + local attention）
- 观察：M2b 的 `shift_random` 注入 lag=7、目标 L=15，测试 `.601`；7+8≈15，疑似“移位 + 局部注意力”两级串联。
- 假说：冻结骨干的长程记忆可以不靠一次长跳，而靠 **多级局部操作**；有效时域 ≈ 深度 × R。
- 实验：target L=15，lr ∈ {1,3,5,7,10,12}；target L=30，lr ∈ {10,15,22}；对照：禁用 backbone 注意力（只留 1 步）应使组合失效。
- 若成立：长记忆的架构是“局部移位 + 多跳 + 课程”，不是 cross-attn 长程寻址；训练可用 curriculum（先 lr=7→15，再 lr=15→30）。
- 失败模式：lr=1 也高 → 不是组合，是价格上下文偏差/泄漏；lr=7 不高 → .601 是单 seed 噪声。

### M17 上下文缩放（判“墙”是不是绝对）
- E6 T=192/384，L=15/30/60，1 seed，cap 8k；对照 T=96 同配置。
- 预测：若 L15 在 T=192 成功而 T=96 失败，则“墙”是相对 reach（R∝T），不是绝对记忆极限；若 T=192 仍失败，墙更硬。
- 成本：T=192 约 2×，T=384 约 4×；先 T=192。
- 注意：位置/时间戳、batch、cap 保持一致；只变 T。

### 统一评测协议
- 冻结骨干；只训 adapter/head；3 seeds；报告 mean±std 与每个 seed。
- 训练/验证/测试按时间切分，测试区间不参与任何选择；同时报 best-val 选点与 last-step，防止记忆化 checkpoint。
- 对照至少包含：none、shuffled m、random fixed Q/K、param-matched MLP、lag 泛化、L=0 正控。
- 所有表格同时报参数量、序列长度、单步延迟、注入/激活幅度比，防止“用算力换准确率”或“信号太弱导致假阴性”。

### 规模/模型族外推（限制）
- Kronos-small 只有 8 层、d=512；L*≈10 不能直接外推到更大模型或别的数据分布。
- 最小验证：在同一个合成任务上换一个 12–16 层的小 GPT（从零预训练在价格 token 上），测 α(L) 与 L* 是否随深度/训练变化。
- 另一个方向：RWKV/SSM 没有注意力；它的状态是固定大小、天然局部可读。测冻结状态对 c_{t-L} 的线性可解码性，比较“attention 的读墙”与“SSM 的状态饱和”。
- **已实测（RWKV7-0.4B，零训练，n=640，单 seed）**：state 对 c_{t-L} 的 AUC：L=0 1.00、L=1 1.00、L=5 .76、L=10 .71、L=15 .67、L=30 .53、L=60 .51；随机 w 对照 .55。固定状态的可解码时域≈15 步，30 步后归 chance；没有 attention 的硬墙，但同样有限。**换骨干不解决长记忆；长记忆必须外置、可寻址。** Caveat：注入在 embedding、零训练、单 seed；训练读出可能延长，但容量不是瓶颈（bit 只占 1/65536），衰减/干扰才是。

## 11. 研究 program（诊断之后）

核心口号：**记忆上限不是时间，是容量 × 寻址。** 把“能记多久”换成“能记多少、怎么找到”。

A. **固定槽记忆**：K 个可学习 slot，因果写入、可训练读出（Perceiver/Flamingo 式）。把 horizon 与 context 长度解耦，推理 O(K)，显存恒定。先验证 slot 版能否在 L=30/60 达到全序列 cross-attn 的水平。

B. **事件门控写入**：不是每个 tick 都值得存。学习一个 write gate（surprise/volatility/流动性/新闻），只在 salience 高时写。相同 S 下减少干扰，可能把有效 horizon 提高数倍。可证伪：固定 S，门控 vs 全写的容量曲线。

C. **多时间尺度状态**：快状态（秒–分钟，波动/订单流）+ 慢状态（小时–日，regime/资金费）。单 GRU 只有单一衰减；分层状态应能同时服务 1m 执行和 1h 配置。可证伪：两个时间尺度的任务，分层 vs 单层。

D. **内容寻址而非位置寻址**：交易里更有用的问题是“上次状态相似时发生了什么”，不是“t-L 的 tick”。用 key-value memory（状态 key、结果 value）+ 可训练 query；先做 M10，再做真实市场状态检索。

E. **审计与回滚**：状态是全局可变变量，必须能快照、重放、A/B。每 N 步落一次全量重算校验点，divergence 超阈值就冷启动。这是工程红线，不是研究可选项。

F. **训练目标**：next-token 不是记忆任务的好目标。用 retrieval/contrastive/净收益目标训练 adapter；骨干冻结，adapter 低秩/门控，避免覆盖预训练特征。M7 量化“加 adapter 的代价”。

三个可证伪问题：
1. 固定容量 S 下，horizon 是否与 L 无关，只随任务熵（需要记住的独立事件数）变化？
2. 事件门控能否在相同 S 下把有效 horizon 提高 ≥2×，且不损失短 lag 精度？
3. 内容寻址能否泛化到训练中未见的 key 组合？若只能记住训练出现过的 key，它不是记忆，是查表。

**接口 trade-off（当前证据）**：

| 接口 | 成本 | 容量 | 泛化 | 适用 |
|---|---|---|---|---|
| bypass（原始观测留在过去） | 低（每层 MLP） | KV 无上限 | **差**（L15 chance） | 不推荐 |
| GRU/SSM 摘要（当前步） | O(1) 状态 | S（128–256） | 固定 lag 好（.981）；变 lag 待 M6 | 流式状态、风险闸门 |
| cross-attn + 相对位置 | O(K) | K slots | 变 lag 冒烟 .83–.87；待 full | 内容/事件检索 |
| 局部组合（shift + local attn） | O(depth) | D×R | 待 M16 | 便宜的長时域 |
| 固定 KV 编辑（ΔK/ΔV） | 中 | 随 L 增长 | 无位置→只改幅度；待 Step2 | 不推荐 |
| 微调骨干 | 高 | 原 KV | 待 M11 | 最后手段 |

没有“全能接口”：摘要适合连续状态，cross-attn 适合内容检索，组合适合便宜的长跳。原研究的 bypass 是三者都不占：存了但不压缩、也不寻址。

## 14. 当前可对外讲的结论（中文，带 caveat）

1. **流式机制的数值等价成立，但“记忆”不在 KV cache 里。** 缓存能存下历史 K/V；能不能用到，取决于 query 能不能找到那个位置。
2. **冻结骨干的自然读很弱，而且 R 随上下文缩放。** 零训练、幅度对齐后：L=1 `.632`、L=5 `.546`、L=10 raw `.526` / cross-fit `.516`（置换 p99 `.523`）、L=15 `.527/.521`。扣除“64 站点取 max”的选择偏差后，**L≥10 基本是噪声**。注意力回看不是常数：Kronos T=96 L*≈14、T=192 ≈22（~0.1T）；Qwen T=96 5.1、T=192 9.4（~0.05T）。所以 T=96 的 L15 墙可能只是刚好超过 R≈14，M17 待测。
3. **E6 训练后的 bypass：L=10 有边缘、种子依赖的增益，L=15 零效应。** 去重后：multis L10 `.605`（n=4；4k `.617`；range .566–.622）vs emb `.524`（n=6）；干净的 4k 三点网格是 `+9.5pp，3/3`。但两个警钟：L5 emb test `.545` 与零训练自然读 `.546` 相同（训练在 test 零收益）；长训 s0 把 L10 test 从 `.6207` 拉到 `.5662`，val 反而升到 `.7425`。`best_val` 是 winner's curse；对外只报 test。
4. **存储没坏，而且在自然写入 SNR 下成立。** E3：a=0.004（每维 0.1σ）force L15 `.984–.985`、L60 `.944–.984`；natural `.50–.56`；uniform `.53–.58`；wrong `.50–.52`。**寻址是唯一瓶颈**，不是写入幅度，也不是容量。
5. **固定滞后是延迟线，不是记忆。** FIR-16（32 参数线性滤波）L=15 ridge **1.0000**、L=30 `.4995`、L=60 `.5000`；GRU `.981` 只是实现了一条 16-tap buffer；shift `.695` 是过拟合（gap .30）；bypass `.514`。**固定 lag 的正确工程是 buffer，不是循环/注意力。** 真正未证的是变 lag/内容（M6/M10）。
6. **因此，原研究的“机制成立、交易无 alpha”可以统一解释**：模型能流式推进状态，但读不到长程状态；1m 方向本身也没有可学信号。继续加长 cache、加宽 bypass，不会解决。**`multis>emb` 是冗余/容量（E6-long .512 vs .509，+.003），不是“层=hop”；层不能累加延迟（all-current .505、staggered-cur .489，但答案放到第 7 层 L=7 又 1.000）。**
7. **架构方向**：固定 lag 用 buffer/FIR；连续状态（波动/regime/持仓）用 GRU/EMA/SSM（IIR 合法）；变 lag/内容用 cross-attn+相对位置。**不要再把 GRU .981 当“记忆”证据。**
8. **交易方向（待 #2）**：内容寻址（“上次状态相似时发生了什么”）比位置寻址（“t-L 的 tick”）更有用；1m taker 方向应停止，转向事件驱动、maker+长持有、风险闸门。
9. **真正剩下的问题**：不是固定 lag，而是变 lag、内容寻址、连续状态、时段泛化。这四者才是 #1 的下一阶段。

## 21. #1 最终结论（2026-11-15）

1. **存储不是瓶颈。** 自然写入 SNR（a=0.004，0.1σ/维，3 seeds）下，强制寻址在 L15/60 读出 `.984/.944`；natural/uniform/wrong 全 `.52`。
2. **固定滞后是 buffer，不是记忆。** 1 参数 tap oracle `1.000`；33 参数 FIR-16 L15 `1.000`/L30 `.501`；69k 等参 MLP `1.000/.500`；GRU 3/3 全桶 `1.000`（单槽 latch）。
3. **层不能制造/累加地址。** 1/2/8 site 全 `1.000`（当 cue 是目标）；all-current `.505`、staggered-cur `.489`、L7 current `1.000`。`multis>emb` 是冗余（`.512 vs .509`）。

## 17. 共同指挥最终判定（E3+FIR 后）

**最强 claim**：在自然写入 SNR（a=0.004，≈0.1σ/维）下，只要给定地址，L15/L60 就能读出 `.984/.944–.984`；本任务的瓶颈是**寻址**，不是写入保真度，也不是容量。

- 连续状态（慢 IIR）：有限 tap 的结构性缺口；

### E4 学到的寻址（pointer/marker）
- 流：`m_t=[c_t, marker_t]`，`c_t` iid ±1，`marker_t∈{0,1}`；在 `[0,t-1]` 随机选一个位置 s 置 1；目标 `y_t=c_s`。

- 臂：FIR-16（只看最近 16）、GRU-128、crossattn+PE、bypass；参数对齐。

- 判定：crossattn 在 lag>16 的 acc ≥.85 且 FIR/GRU ≤.55 → 学到寻址；否则没有。

## 16. 推荐架构：streaming sidecar（基于当前证据）

**一句话**：不要把记忆交给冻结骨干的 KV cache；用一个 O(1) 的 sidecar 状态维护历史，把状态注入当前步，让骨干只做局部精读。

```
每根 bar t:
  x_t = [return, realized vol, OFI/imbalance, spread, position, time, ...]   # 紧凑特征
  h_t = f(h_{t-1}, x_t)                       # GRU / SSM / 多时间尺度 EMA
  tokens_t = embed(price tokens at t)
  z_t = tokens_t + gate * MLP(h_t)            # 只注入当前位置（局部）
  decision = head( backbone(z_t) , h_t )      # 骨干 + 状态一起读
```

- **f**：连续状态（波动/regime/持仓）用 GRU/EMA/SSM；**固定滞后用 16-tap buffer/FIR**（FIR-16 L15 `1.0000`，L30 `.4995`）。GRU `.981` 只是 buffer 的一个实现，不是通用记忆。变 lag/内容用 cross-attn+相对位置。
- **gate/MLP**：初值 0，冻结骨干，只训 sidecar + head；低秩/门控防止覆盖预训练特征。
- **content memory（可选）**：固定 K 个 slot，key=状态、value=结果；cross-attn 查询“上次状态相似时发生了什么”。这是交易更需要的，但需要 M10 证明。
- **审计**：h_t 可快照/回放；每 N 步与全量重算校验；状态维度固定，显存 O(1)。

**为什么不是 KV cache**：M12 证明 KV 里有信息，但冻结 query 找不到；M2b 证明把摘要放到当前位置几乎满分。KV 继续增长不会提升可读性，只会增加显存和攻击面。

**替代解释（必须认真对待）**：不是 storage/addressing/read 三段，而是单一量——**冻结先验上“可学习读操作”的等效带宽**。接口差异 = 给“学一个新相对偏移”多少梯度路径/参数/注入 SNR。它预测 L* 与任务熵无关、随 token 率与 warm-start 变；三段论不预测这些。
